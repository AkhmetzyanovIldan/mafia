# 03. Game Engine

## Назначение
Game Engine полностью управляет жизненным циклом партии. Клиент не содержит игровой логики.

## Game Loop
LOBBY → ROLE_ASSIGNMENT → NIGHT_CHECKS → NIGHT_KILLS → MORNING → LAST_WORD (опционально) → DISCUSSION → VOTING → CHECK_WIN → GAME_END / NIGHT

## Game State
Хранится на сервере.
- Phase
- RoomSettings
- Players
- Timers
- ActiveActions
- GameResult (после окончания)

## Player State
Для каждого игрока:
- Role
- Team
- VotePower
- Alive
- CanVote
- CanSpeak
- CanUseNightAbility
- TemporaryStatuses

## Role Model
Роль содержит:
- Id
- Name
- Team
- VotePower
- Abilities

Игровая логика роли отсутствует.

## Player Action
Каждое действие:
- Actor
- Ability
- Target
- Timestamp
- Confirmed

После подтверждения действие изменить нельзя.

## Night Flow

Ночная фаза делится на два последовательных подэтапа с мгновенной персональной обратной связью:

### Подэтап 1: Активные действия и проверки (Parallel Actions Timer)
1. Все роли с ночными способностями (Комиссар, Дон, Врач, Журналист, Любовница, Адвокат) совершают выбор одновременно в рамках единого таймера активных действий.
2. **Мгновенный ответ:** Как только игрок подтверждает выбор, движок немедленно вычисляет персональный результат и отправляет его **только этому игроку** через индивидуальное WebSocket-событие:
   - **Комиссар / Дон / Адвокат / Журналист:** моментально видят результат проверки своей цели.
   - **Врач:** моментально получает информацию о том, кого он вылечил.
   - **Выбранный Врачом игрок:** моментально получает уведомление, что его вылечил врач.
   - **Любовница:** выбирает цель, а выбранный игрок моментально получает уведомление, что у него была любовница.
3. Остальные участники игры никакой информации не видят. Если игрок не успел сделать выбор до истечения таймера, действие считается пропущенным.

### Подэтап 2: Ночные убийства (Night Kills Timer)
1. После завершения таймера активных действий открывается таймер ночных убийств.
2. Для Мафии, Дона и Сержанта открывается интерфейс выбора жертвы (цели для устранения).
3. После окончания таймера сервер вычисляет итоговый урон, учитывает блокировки Любовницы и формирует окончательный список жертв.
4. Наступает утро (`Morning Flow`).

### Обработка сетевых задержек (Grace Period)
* **Буферное окно (Grace Period):** При завершении любого ночного таймера (`ACTIVE_NIGHT_TIMER` или `NIGHT_KILLS_TIMER`) сервер закладывает дополнительный технологический интервал в **500 миллисекунд**.
* Все пакеты от клиентов, отправленные до истечения таймера, но пришедшие на сервер в течение этого буферного окна (из-за пинга), **принимаются в расчет**.
* Пакеты, пришедшие после истечения Grace Period, отклоняются сервером, а действие считается пропущенным (`action_skipped`).

## Политика бездействия и пропусков хода (AFK & Pass Policy)
* **Пассивный пропуск (Воздержание):** Отсутствие действия со стороны игрока во время любой фазы (активная ночь, ночное убийство или дневное голосование) не является ошибкой или причиной для зависания игры.
* **Дневное голосование:** Если игрок не выбрал цель для голосования до конца таймера, его голос считается **пропущенным (воздержался)**. Система не принуждает его голосовать случайно и не зачитывает голос против кого-либо.
* **Ночная фаза:** Если ролевой игрок (Комиссар, Врач, Мафия и т.д.) не подтвердил выбор до истечения таймера (с учетом Grace Period), действие **сгорает** (эффект роли не применяется, ночь продолжается/завершается по таймеру).

### Проверка условий победы
* Отсутствие выбывших при повторной ничьей не останавливает игровой процесс.
* Системная проверка условий победы мирного и мафиозного кланов проводится автоматически **дважды за игровой круг**:
  1. **Утром:** сразу после завершения ночных расчетов и оглашения результатов ночи.
  2. **Вечером:** сразу после завершения дневного голосования (включая ситуации с ничьей и отсутствием выбывших) перед наступлением следующей ночной фазы.
* Если по итогам проверки один из кланов достигает условий победы (например, число мафии сравнялось с числом мирных или мафия полностью уничтожена), игра немедленно завершается фазой победы.

## Effect Любовницы
После обработки ночи:
- днем игрок не голосует;
- следующей ночью не использует способность.

## Morning Flow
- объявление погибших;
- если включено — последнее слово;
- выступления игроков;
- голосование.

## Voting
- один подтвержденный голос;
- изменить нельзя;
- отсутствие голоса не считается голосом.

После голосования:
1. Игрок становится мертвым.
2. Проверка победы.
3. Объявление результата.
4. Последнее слово (если включено).
5. Следующая ночь либо GAME_END.

## Timer Engine
Серверные таймеры:
- проверки;
- убийства;
- последнее слово;
- выступления;
- голосование.

## Server Validation
Сервер проверяет:
- текущую фазу;
- право использовать способность;
- корректность цели;
- повторные запросы;
- состояние игрока.

Недопустимые действия отклоняются.

## Reconnection
Игрок сохраняет место, роль и состояние.
Если таймер закончился — действие считается пропущенным.

### Защита при переподключении в критические фазы
* **Атомарный снепшот состояния:** При переподключении игрока (обрыв связи, обновление страницы) сервер отправляет не просто текущие сырые данные, а полный транзакционный пакет (`Full State Snapshot`), включающий текущую фазу, оставшееся время таймера и статус блокировки интерфейса.
* **Подавление локальных анимаций:** Клиент обязан принимать этот пакет с флагом блокировки (`is_transitioning: true`), который временно замораживает любые локальные переходы или анимации смены фаз до тех пор, пока клиентский рендерер полностью не перерисует игровой стол под актуальные данные сервера.

## Observer
Наблюдатель:
- не имеет роли;
- не голосует;
- не выполняет действия;
- не получает закрытую информацию.

## Win Conditions
Победа определяется суммой прав голоса живых игроков.

Базовое значение:
- все роли = 1.

Исключения:
- Комиссар = 2;
- Врач = 2;
- Любовница = 2.

Мафия побеждает:
VotePower(Mafia) >= VotePower(Citizens)

Мирные побеждают:
VotePower(Mafia) == 0

## Основные принципы
- Сервер является единственным источником истины.
- Клиент только отображает состояние.
- Любое действие требует подтверждения.
- Подтвержденное действие изменить нельзя.
- Все вычисления выполняются сервером.
